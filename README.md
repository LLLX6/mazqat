# مزاد مسقط — MAZQAT

تجربة عربية RTL لمزاد حي بطابع عُماني. صُممت الواجهة بلغة بشرية سريعة المسح: أقسام مربعة ملوّنة، مساحات فاتحة، كحلي وتركواز، وحالات واضحة بدل ازدحام الأرقام.

> هذه النسخة **معاينة تفاعلية** ببيانات وهمية. لا يوجد بيع أو دفع أو بث عام حقيقي، ولا ينبغي إدخال بيانات شخصية حقيقية فيها.

## ما يعمل الآن

- اكتشاف المزادات الجارية والقادمة، أقسام المعروضات، البحث والفرز.
- غرفة مزاد حية تجريبية بسعر حالي، مؤقت، أعلى 3 مزايدين، زيادات يحددها المنظم، انسحاب، وتمديد منع القنص.
- تأكيد واضح قبل إرسال العرض، ثم تثبيت الفائز ورسالة خاصة بخيارات الاستلام أو التوصيل.
- حساب المزايد وتفضيلاته، صندوق رسائل نظام، ولوحة مالك للطلب والمبيعات والفريق والصلاحيات.
- استوديو كاميرا محلي مع فلاتر ومعاينة آمنة؛ لا تُرسل الصورة خارج الجهاز في وضع المعاينة.
- PWA خفيفة، RTL متجاوب، حالات اتصال/انقطاع، ودعم لوحة المفاتيح وتقليل الحركة.
- محرك مزايدة اختباري مستقل، ونموذج D1 اختياري معطّل افتراضيًا لاختبارات الفريق الخاصة فقط.

## التشغيل

يتطلب Node.js 22.13 أو أحدث؛ تستخدم CI إصدار Node 24.

```bash
npm ci
npm run dev
```

افتح `http://127.0.0.1:4173/`.

```bash
npm run check          # اختبارات + TypeScript + ESLint
npm run build:static   # معاينة GitHub Pages داخل static-dist
npm run build          # حزمة OpenAI Sites/Vinext على Linux
```

## حدود الصدق التشغيلي

المعاينة المنشورة على GitHub Pages تحفظ المزايدات في جلسة المتصفح فقط. نموذج `/api/auction` معطّل افتراضيًا، ولا يجوز فتحه للعامة: لا يضم تسجيل دخول إنتاجيًا ولا إغلاقًا زمنيًا موثوقًا على الخادم. يمكن تشغيله داخل تجربة فريق خاصة فقط عبر D1 و`DEMO_SHARED_BIDS=enabled-anonymous-demo`.

الإنتاج الحقيقي يحتاج Supabase/PostgreSQL أو قاعدة موثوقة مماثلة، LiveKit للبث، تسجيل دخول وهويات موثقة، مزود رسائل، دفع موثوق، سياسات السلع والخصوصية، ومراجعة قانونية داخل عُمان. راجع [بوابات الإصدار](docs/RELEASE.md).

## البنية المختصرة

```text
المضيف ── فيديو ──> LiveKit (الإنتاج)
المزايد ── طلب عرض ──> API موثوق ──> قاعدة البيانات ──> بث النتيجة للعملاء
                                           └─> نتيجة + طلب + رسالة خاصة + audit
```

السعر يُخزّن بالبيسة كعدد صحيح، ولا يعتمد قرار قبول المزايدة أو الإغلاق على ساعة الهاتف أو WebSocket العميل.
